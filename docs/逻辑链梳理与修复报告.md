# ScriptWeaver 功能逻辑链梳理与修复报告

> 范围：以用户反复反馈的「.rpy 导入」为核心，向外延伸到素材解析、舞台渲染、音频播放、Ren'Py 导出等全链路；对每一条链逐段标注数据形态与关键约定，并列出本次发现并修复的不一致点。
> 验证状态：tsc 0 错误；rpyExporter(49) + rpyImporter(62) 共 111 测试全过；4 个真实工程（lulu / hlzz / siyu / SW）实地导入验证；Electron 窗口已重启加载新代码。

---

## 一、总体数据流

```
.rpy 源文件
   │  importRpyDirectory → parseRpy → scanAssetFiles → matchAssets
   ▼
中间态 RpyImportResult（引用用占位符：sw-asset: / sw-video: / sw-audio:）
   │  RpyImportDialog（Step1~5 预览、分组、角色绑定、变量、背景重映射）
   ▼  fsImport(真实落盘，按 kind 给 type)
store：assets / draftDeltas / characters / variables
   ├─► 渲染：StagePreview 消费 asset_id + resolveAssetSrc（sw-asset:// 协议）
   ├─► 播放：音频经 AudioManager 试听/播放
   └─► 导出：rpyExporter 逐行 reduce + buildSymbolTable → .rpy（往返一致）
```

主进程与渲染进程分工（铁律约定）：渲染端只持有「元数据 + relativePath」；主进程通过私有协议 `sw-asset://` 流式直读真实磁盘文件，密钥托管在 userData 安全区。

## 二、各功能逻辑链

### 1. .rpy 导入链路（最复杂，本次重点）

入口：`RpyImportDialog` → `importRpyDirectory(root)`，逐文件 `parseRpy`。

**1.1 解析（parseRpy）**
- 收集：`label` / 对白 `speaker + dialogue` / `scene`(→背景) / `show`(→立绘) / `image` 声明 / `play sound|music|voice` / `Movie(play=)` 与 `renpy.movie_cutscene`(→视频背景) / `define X = Character(...)` / `default X = ...`(→变量) / `menu:`(→选择支)。
- 产出 `draftDeltas` 为**中间态**：背景引用写成 `sw-video:<文件名>`，音频写成 `sw-audio:<名>`，图片按 refName。此时尚未绑定真实素材 id。

**1.2 扫描（scanAssetFiles）**
- 递归 walk 工程目录，按扩展名分桶：`images`(png/jpg/webp…)、`audio`(wav/mp3/ogg…)、`video`(webm/mp4/ogv/mkv/mov/avi/m4v)。视频桶独立于目录，避免视频漏识别（前次已修）。

**1.3 引用匹配（matchAssets）**
- 优先级①：用 `ref.path` 显式路径末段匹配，`usedImageFiles` 集合防同一文件被多个 ref 复用（解决同名文件冲突）。
- 优先级②：同目录同名。
- 优先级③：按 `refName` 模糊匹配。**本次修复**——原逻辑无 `break`，多个文件名都包含 refName 时取遍历的最后一个（依赖目录顺序、不稳定）。改为带分制最佳匹配：精确(100) > `ref_` 分隔符前缀/后缀(60) > 中间含(50) > 起止含(40) > 仅包含(20) > ref 含文件名(10)。
- 分类：`scene X` → `background`，`show X` → `sprite`（`usage` 字段）；未出现的图片走令牌启发式（`bg|background|cg`）。

**1.4 弹窗编排（RpyImportDialog Step1~5）**
- Step1 总览；Step2 分组落盘（背景/立绘/音频/视频分别 `fsImport`，主进程按内容 SHA1 去重，杜绝 `_N` 副本）；Step3 角色绑定；Step3.5 立绘→角色；Step4 变量；Step5 背景重映射 + 落库。
- 重映射：把 `sw-video:<名>` / `sw-audio:<名>` 替换为 `Step2` 真正落盘后得到的素材 id（存于 `importedVideoMap` / `importedAudioMap`，key 为 refName）。

**1.5 落库（store）**
- `setAssets(去重后)` / `setDraftDeltas` / `setCharacters` / `setVariables`。素材 `type` 由 `fsImport(kind)` 正确赋值（`background|sprite|audio|video|effect`），下游全部按 `type` 过滤。

### 2. 素材解析链路（sw-asset:// 协议）

- `resolveAssetSrc(assetId)`：查 `store.assets` 得到 `relativePath` → 拼成 `sw-asset://<rootKey>/<relativePath>`。
- 主进程 `protocol.handle('sw-asset')`：按真实磁盘路径直读；图片/音频分别支持整文件与 `Range` 206 响应（音频必须 206 否则播不出）。
- 铁律1：禁止 Base64 常驻；所有消费端走 `<img src>` / `<audio src>` 直读，禁用 CSS `background-image` 套 sw-asset 协议（舞台背景已用 `<img>` 修复）。

### 3. 舞台渲染链路（StagePreview）

- 数据来源：`draftDeltas[activeLine]`，读出 `background.asset_id` / `characters[].asset_id` / `audio`。
- `computeZone`：按 `asset.type` 把素材分流到背景区(`background`) / 立绘区(`sprite`) / 音频。
- 视频背景：`isVideoBg` 决定渲染 `<video>` 还是 `<img>`，并提供循环开关。**本次修复**——原仅判断 `asset_id` 是否以 `sw-video:` 开头，但导入链路已把前缀重映射成真实素材 id，导致导入后的视频背景被当图片渲染（.webm 当 `<img>` 源）。改为「前缀 `sw-video:` **或** 素材 `type==='video'`」双判定。
- 交互铁律2：单拖动改坐标、双击开属性面板、键盘 Delete 直接删除并单事务同步时间轴。

### 4. 音频播放链路

- 导入后 `audio.bgm/voice/se` 的 `asset_id` 应为真实哈希素材 id。
- **本次修复**：`Step5` 原用 `.replace(/\.[^.]+$/, '')` 去剥「扩展名」，但解析产物是带 `sw-audio:` 前缀的（如 `sw-audio:nhjj`），去掉扩展名后仍带前缀 → `importedAudioMap.get('sw-audio:nhjj')` 查空 → 音频绑定失败、预览放不出声。改为 `replace(/^sw-audio:/, '')` 正确去掉前缀，命中真实素材 id。
- 播放：`resolveAssetSrc` 解析 → `AudioManager` 播放；范围请求走 206。

### 5. Ren'Py 导出链路（rpyExporter，往返一致）

- `buildSymbolTable`（Pass1）：构建 `speakerToCharId` / 角色表情表 / `bgDefs` / `audioDefs` / `videoDefs` / `slots`。**本次修复**——新增 `videoDefs`（此前 block 构造闭包内无 `assets`，无法按 id 查视频素材）。
- 逐行 `reduceLines` 继承链 + 生成 `block`：`scene`/`show`/`hide`、对白、`play music/sound/voice`、`menu`、过渡。
- 视频背景：**本次修复**——原仅 `startsWith('sw-video:')` 判定，导入后真实 id 丢失前缀 → 落入 `else` 分支且 `bgDefs` 不含视频素材 → 导出成 `[缺失背景]` 注释。改为「前缀 **或** `type==='video'`」双判定，取 `asset.fileName` 写 `Movie(play="video/<clip>", loop=True/False)`。
- 铁律4：过渡走 `BUILTIN_TRANSITIONS` 白名单 + `resolveTransition` 自动生成 transform；缩放走 `sw_zoom`/`sw_pos`，禁非法 `zoom()`。

### 6. 变量 / 角色 / 选择支（简述）

- 变量：`default X = ...` → `variables`，UI 变量监视器（Dock）可读写。
- 角色：`define X = Character(...)` → `characters`，支持表情包、主题色、声色绑定。
- 选择支：`menu:` → `choices`，导出为 `menu:` 块，可绑定 `jump` 标签与变量操作。

## 三、发现并修复的问题（汇总）

| # | 位置 | 问题 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | `RpyImportDialog` Step5 音频 | 导入后 bgm/voice/se 音频绑定失败、预览无声 | 用 `.replace(/\.[^.]+$/,'')` 去扩名，未去 `sw-audio:` 前缀，`importedAudioMap` 查空 | 改为 `replace(/^sw-audio:/, '')` |
| 2 | `StagePreview` `isVideoBg` | 导入后的视频背景被当图片渲染 | 仅判 `sw-video:` 前缀，导入侧已重映射成真实 id | 加 `asset.type==='video'` 双判定 |
| 3 | `rpyExporter` 视频背景 | 导入后的视频背景导出成 `[缺失背景]` 注释 | 仅判 `sw-video:` 前缀，且 block 闭包无 `assets` 查表 | 新增 `videoDefs` 查表 + `type==='video'` 双判定 |
| 4 | `rpyImporter` matchAssets 优先级③ | 多文件都含 refName 时匹配结果依赖遍历顺序、可能选错 | 模糊匹配无 `break`，取最后一个 | 改为带分制最佳匹配 |
| 5 | `web-player/player.js` `isVideo` | 导入项目发布到 Web 播放器后视频背景不被识别 | 仅判 `sw-video:` 前缀 | 加 `assetMap[id].type==='video'`（web 导出已带 type，向后兼容） |

> 附带：上一轮已修的「背景/立绘不分、视频漏识别、重复图」在 4 个真实工程实地验证均正确；SW 工程 0 图匹配属「工程本身缺图文件」的正确告警，非解析 bug。

## 五、遗留与建议

- **layeredimage / 复合图**：SW 工程用 `image alice angry = ...` 复合声明且磁盘无图，目前正确告警；若后续要导入 layeredimage，需解析块内 `group/attribute` 引用的组件图。当前不在本次范围。
- **同名不同目录冲突**：两张同名 `b.png` 分处 background/sprite 目录时，`byStem` 仅留其一，依赖 `ref.path` 精确指向各自文件；若工程中两 ref 声明指向同一物理文件，后者会因 `usedImageFiles` 去重而报未匹配，属预期（共享同一素材）。
- 建议：导入后可加「未匹配引用」清单面板，便于用户手动补素材（目前只有 console.warn + 警告计数）。
